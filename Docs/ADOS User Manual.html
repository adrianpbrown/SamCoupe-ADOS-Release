ADOS User Manual

Version 1.2 · 25 November 2026 · Adrian Brown

1. Introduction

ADOS is one DOS for the SAM Coupé. It replaces SAMDOS, BDOS (Trinity) and AL-BDOS (Atom Lite), reads and writes MasterDOS disks, and adds PC FAT16 and FAT32 cards and drives. You load it once and every drive you own is available under its own letter.

ADOS fits in one 16K DOS page. Its start-up code is thrown away after boot and the memory is reused for buffers, so ADOS uses no more memory than SAMDOS.

What ADOS gives you

  • One DOS for all your storage: floppy drives, the Atom Classic and Atom Lite IDE interfaces, and the Trinity SD card interface.
  • Drive letters: each disk, BDOS record container or FAT partition is a drive with a letter, such as A: or D:.
  • SAMDOS and MasterDOS compatibility: disks made by SAMDOS, MasterDOS, BDOS and AL-BDOS work as they are. The error numbers match SAMDOS, so programs that trap DOS errors still work.
  • MasterDOS directories: subdirectories, paths in file names and date stamps on SAM disks.
  • BDOS records: a BDOS card or hard drive holds many 800K records, each of which behaves like a floppy disk.
  • PC cards and drives: a card or drive formatted on a PC as FAT16 or FAT32 is one large drive, with long file names and folders. ADOS reads and writes it, and a PC can read the files ADOS saves.
  • COPY between any drives: single files, wildcards, and whole disks, with a percentage shown as it goes.
  • SAM disk images on FAT: an 800K .MGT file can be used as a folder or mounted on a drive letter, and works like a real floppy.
  • Real-time clocks: files you save are stamped with the date and time when a clock is fitted, on SAM disks and FAT drives.

About this manual

This manual describes ADOS version 1.2 as it stands on 25 November 2026. Features still to come are collected in Appendix C. Section 5 is the reference for every command; the other sections explain how to use them.

You should already know SAM BASIC. Where ADOS works the same as SAMDOS (for example SAVE and LOAD), this manual describes only what is different.

2. Getting started

To start ADOS, put the ADOS system disk in drive 1 and press F9, or type BOOT and press RETURN. ADOS checks your hardware, shows what it found, and selects a drive. You can then use BASIC as normal.

The start-up screen

While it starts, ADOS looks for every clock and storage interface it knows about. The screen then shows something like this:

The sizes, labels and devices depend on your hardware.

  • Clock shows the clock found, if any, and the date and time it gives (Not Set if the clock has no sensible date). See Section 8.
  • Detected lines list each interface that answered, its size and the scheme: how the medium is laid out (see Section 3).
  • The indented lines under a device list the drives found on it, with the letter each one was given and, for FAT, the volume label.
  • Current Drive is the drive used when a command does not name one. ADOS chooses the default drive (normally A:). If that drive is missing, it chooses the first letter that has a drive.

Your first commands

  1. Type DIR to list the files on the current drive.
  2. Type DIR "C:" to list the files on drive C: without changing the current drive.
  3. Type DIR = "C:" to make C: the current drive.
  4. Type LOAD "GAME" to load a file from the current drive, or LOAD "A:GAME" to load it from drive A:.
  5. Type SAVE "TEST" to save the BASIC program in memory on the current drive.
  6. Type COPY "A:*" TO "C:\BACKUP\" to copy every file on the floppy to a folder on the card.

Taking care of disks and cards

  • Do not remove a floppy disk, card or drive while it is being read or written. By default the border flashes while ADOS reads or writes (see Appendix B to turn this off).
  • ADOS finds cards and drives when it starts. If you fit a card or drive after booting, reset and boot ADOS again so that it is found.
  • A floppy disk, card, BDOS record or disk image can be write protected. ADOS then reports Protected when you try to change it.

3. Drives, records and partitions

Every drive in ADOS has a letter, and each letter is one SAM disk, one BDOS record container or one FAT partition. A single card can therefore give you several letters, and you never need to know which interface a file is on, only its letter.

Schemes: how a medium is laid out

When ADOS starts it reads the start of each disk, card or drive to find out how it is laid out. The start-up screen calls this the scheme.

SchemeWhat it isDrives it gives
SAMDOSAn 800K SAM floppy disk made by SAMDOS, MasterDOS or ADOSOne SAM drive
BDOSA card or hard drive prepared by BDOS or AL-BDOS, holding many 800K recordsOne drive; use RECORD to choose the record
MBRA PC card or drive with a partition tableOne drive per FAT partition
VBRA PC card formatted as a single volume with no partition tableOne FAT drive
GPTA modern PC partition tableNone (not supported)
UnknownAnything elseNone

A card or drive holds either BDOS records or PC partitions, never both.

How letters are given out

  • A: and B: always belong to floppy drives 1 and 2. D1: also means A:. D2: means the BDOS card in use, as in BDOS, or B: if there is no BDOS card. A floppy drive that is fitted keeps its letter even with no disk in it, and B: stays free for a disk image when there is no second drive.
  • C: onwards go to every other drive and partition, in the order they are found: Atom Lite right bay (master, then slave), Atom Lite left bay, Atom Classic master, Atom Classic slave, Trinity. Each FAT partition, and each set of BDOS records, takes the next letter.
  • Up to 8 letters can be in use at once, counting mounted disk images.

For example, an Atom Classic with two partitions and an SD card as slave gives C: and D: on the hard disk and E: on the card. The letters can change from one boot to the next if you add or remove cards; check the start-up screen, or use DIR "X:" to see what a letter holds.

The letters are always given out this way. Only the drive chosen at boot is stored in the DOS itself (DVAR 47, Appendix B), so it can be changed with POKE and saved with it.

SAM drives

A SAM drive is an 800K disk: a real floppy, one record on a BDOS card, or a disk image on a FAT drive. SAM drives support everything in this manual, including subdirectories and date stamps.

The directory of a SAM disk normally holds 80 entries. Disks made by MasterDOS with larger directories (up to 780 entries) are read and written correctly.

BDOS records

BDOS and AL-BDOS divide a card or hard drive into records. Each record is an 800K SAM disk and can have a 16-character name. A 2G card holds about 1,200 records.

A BDOS drive always has one record selected, and every command on that drive uses it. Record 1 is selected when ADOS starts.

  • RECORD lists the records that have names.
  • RECORD 25 selects record 25.
  • RECORD "GAMES" selects the record named GAMES.

Selecting a record also returns you to its root directory. ADOS reads cards made by both BDOS and AL-BDOS, and the records stay usable by those DOSes.

BDOS programs keep working. ADOS has BDOS’s DOS variables and hook codes, and D2: is the BDOS card. PEEK DVAR 25 gives its current record, and POKE DVAR 25,n selects record n, as in BDOS. BDOS had one card; with a card in the Atom and another in the Trinity, ADOS’s drive 2 and DVARs follow the BDOS card you used last, starting with the first one found. Each card keeps its own record.

FAT drives

A FAT drive is a partition on a card or drive formatted on a PC as FAT16 or FAT32. It is one large drive with folders and long file names, and it is a simple way to move files between a PC and the SAM. ADOS reads and writes FAT drives: SAVE, ERASE, RENAME, OPEN DIR, ERASE DIR and COPY all work on them.

A FAT drive can also hold SAM disk images (Section 6). FAT12, used on very small cards, is shown at start-up but its files cannot be read.

4. File names, directories and paths

A full file name in ADOS is a drive, then a path, then a name: "D:\GAMES\ARCADE\INVADERS". Every part is optional; whatever you leave out comes from the current drive and the current directory.

Drive letters in names

Put the drive letter and a colon in front of a name to use a drive other than the current one:

LOAD "B:MYPROG"
SAVE "C:SCORES" CODE 32768,1000
DIR "D:"

Upper and lower case letters are treated the same. If the letter has no drive, ADOS reports No drive.

Names

  • SAM drives use names of up to 10 characters, as SAMDOS and MasterDOS do. Case is ignored when ADOS looks for a file.
  • FAT drives take long names of up to 64 characters, such as "Manic Miner.bin" (a longer name is cut to its first 64; a file made on a PC with a longer name can still be reached with a wildcard or its 8.3 name). Case is ignored, and a file can be found by its long name or its short 8.3 name (MANICM~1.BIN). A name cannot start with . or contain " * / : < > ? \ |.
  • The whole name, drive and path included, can be up to 255 characters, in ADOS's commands and in LOAD, SAVE, VERIFY and MERGE: SAVE "D:\PICS\HOLIDAY SNAPS.SCR" SCREEN$. The SAM ROM on its own refuses a LOAD or SAVE name over 14 characters. ADOS takes the longer ones on ROM 3.0; with an older ROM the limit stays at 14. Tape names stay at 10.

Wildcards

WildcardMatchesExampleFinds

DIR, ERASE and COPY accept wildcards. SAVE, RENAME, OPEN DIR and FORMAT need a plain name and report Bad file name if it has wildcards.

Directories

SAM drives hold subdirectories in the same way as MasterDOS, and FAT drives have folders. Each drive remembers its own current directory, so changing directory on D: does not affect A:.

In a pathMeans

If a directory in a path does not exist, ADOS reports Dir not found. Directories on SAM drives use the MasterDOS layout, so MasterDOS can read them. SAMDOS and BDOS ignore the directory information and show every file on the disk.

SAM files on FAT drives

A file saved to a FAT drive holds only its data, so a PC can read it as it is. The SAM details (type, name, load and run addresses) go in a hidden file beside it with .info added to the name: GAME.BIN gets GAME.BIN.info. ADOS keeps the two together: ERASE removes both, RENAME renames both, and DIR does not list .info files.

A file with no .info, such as one copied from a PC, loads as CODE. If you do not give an address it loads at 32768. The length always comes from the file's size on the card.

LOAD "music.bin" CODE            : REM loads at 32768
LOAD "music.bin" CODE 40000      : REM loads at 40000

OPEN DIR

Makes a new directory, in the current directory unless the name has a path. On a SAM disk this is a MasterDOS directory; on a FAT drive it is an ordinary folder a PC can use.

OPEN DIR "GAMES"

ERASE DIR

Erases a directory. It must be empty, or ADOS reports Dir not empty. On a FAT drive a hidden .info file still counts as something in the folder.

COPY

COPY name TO name

Copies files between any two drives, SAM or FAT, in either direction. If the target's name is blank or has wildcards, each file keeps its own name. Directories are not copied.

COPY "A:CHAOS" TO "D:\GAMES\CHAOS"      : REM one file, new name
COPY "A:*" TO "D:\BACKUP\"              : REM every file, same names
COPY "D:\PICS\*.SCR" TO "A:"            : REM matching files
COPY "D:README.TXT" TO "D:\DOCS\"       : REM same drive, another folder

While it copies, COPY shows each file's name and how far it has got, from 0% to 100%. The figure counts every sector read and written, so on a small file it can reach 99% early and then stay there until the file is finished.

As in MasterDOS, a file bigger than free memory is copied in several passes, so any file can be copied whatever its size. COPY needs at least 32K of free memory in one block; with less it reports No memory. The more memory is free, the fewer passes it takes.

The copy keeps the file's type and addresses. The copy is dated when it is made, as if it had just been saved. A PC file copied from one FAT drive to another gains a .info.

Whole disks. If one side is only a drive letter and that drive is a SAM disk, COPY copies the whole disk, every track and sector, and shows a percentage as it goes. The target is overwritten completely.

COPY "A:" TO "B:"                 : REM floppy to floppy
COPY "A:" TO "D:\BACKUP.MGT"      : REM floppy to a disk image (made if it isn't there)
COPY "C:" TO "D:\RECORD5.MGT"     : REM the current BDOS record to a disk image
COPY "D:\BACKUP.MGT" TO "A:"      : REM disk image to a floppy (it must be formatted)

FORMAT

FORMAT name

Makes a new, empty SAM disk image (819,200 bytes) on a FAT drive. If the name is already used, ADOS reports File name used. FORMAT does not format real floppies; on a drive that isn't FAT it reports Bad device.

FORMAT "D:\WORK.MGT"

OPEN "X:" TO and CLOSE "X:"

OPEN "X:" TO name
CLOSE "X:"

OPEN gives a disk image its own drive letter until CLOSE or reset. The letter must be free, or ADOS reports Bad device. If the closed drive was the current drive, ADOS goes back to the default drive. OPEN # and CLOSE # (streams) are still the ROM's.

OPEN "B:" TO "D:\GAMES\CHAOS.MGT"
LOAD "B:chaos"
CLOSE "B:"

RECORD

Works on the current drive, which must be a BDOS drive; otherwise ADOS reports Bad device. RECORD on its own lists every record that has a name, with its number. RECORD n or RECORD name selects a record; case is ignored. If the record does not exist, ADOS reports No record. Select the drive first with DIR =:

DIR = "C:"

On a FAT drive, RECORD "CHAOS.MGT" does the same as DIR = "CHAOS.MGT", and RECORD 0 leaves the image (but not a mounted one: use CLOSE).

BOOT and F9

F9 loads and runs the file whose name starts with AUTO on the current drive, in the current directory. If there isn't one, nothing happens. BOOT does the same once ADOS is loaded, but reports No AUTO file if there isn't one. The AUTO file must be BASIC, CODE or SCREEN$; BASIC programs run from their auto-start line.

6. Disk images

A FAT drive can hold SAM floppy disk images. Software that needs a SAMDOS or MasterDOS disk runs from an image unchanged. There are two ways to use one:

  • As a folder. Go into the image with a path: DIR = "D:\GAMES\CHAOS.MGT". While inside it, the drive works as a SAM floppy. .. from the image's root goes back to the FAT folder that holds it.
  • Mounted on its own letter. OPEN "B:" TO "D:\GAMES\CHAOS.MGT" makes B: a SAM floppy until CLOSE "B:". This suits software that only uses certain drives, and games on more than one disk. A mounted drive stays inside its image.

An image can also appear in the middle of a path: LOAD "D:\GAMES\CHAOS.MGT\chaos".

Which files are images

  • An image is any file of exactly 819,200 bytes, whatever its extension (.MGT, .DSK, or none): the raw 800K disk in MGT order. EDSK and SAD files are not read.
  • An image need not be in one piece on the card, but must be in no more than 12 pieces, or ADOS reports Fragmented. Copy it to another drive and back, or defragment the card on a PC.
  • An image that is read-only on the FAT drive reports Protected when written to.
  • An image that is mounted, or that a drive is inside, cannot be erased or saved over. RENAME is still allowed.

Use FORMAT to make a blank image, and COPY to copy a whole disk to or from one (Section 5).

7. Interfaces

ADOS finds every supported interface by itself when it starts; there is nothing to set up. This section gives the details that matter when you fit or swap hardware.

Floppy drives

Floppy drives read and write 800K SAM disks (80 tracks, 2 sides, 10 sectors of 512 bytes), the same format as SAMDOS and MasterDOS. The drive motor stops after a short time with no activity.

Atom Classic

The Atom Classic is a 16-bit IDE interface for a hard drive or CompactFlash adapter, with a master and a slave. It uses the ports of floppy drive 2. Drives prepared by BDOS hold BDOS records, read in the byte order BDOS used so that BDOS can still read them. Drives formatted on a PC hold FAT partitions. ADOS uses LBA addressing, so drives larger than 8G can be used for FAT32.

Atom Lite

The Atom Lite is an 8-bit CompactFlash interface with two bays. The right bay uses the ports of floppy drive 2 and the left bay those of floppy drive 1. Each bay can hold a master and a slave card. Cards prepared by AL-BDOS hold BDOS records, and AL-BDOS can still read them after ADOS has used them. Cards formatted on a PC hold FAT partitions.

Trinity

Trinity is an SD card interface. ADOS reads and writes cards prepared by BDOS, and PC-formatted FAT cards. BDOS supported only SD cards up to 2G; ADOS also supports SDHC cards (4G to 32G), which is what most FAT32 cards are.

SDHC support has not yet been tested on real hardware. If an SDHC card is not found, try a 2G SD card.

Using cards made on a PC

  1. Partition the card or drive with an MBR ("Master Boot Record" in the PC's disk tool), not GPT. A card formatted as one volume with no partition table (a "superfloppy") also works.
  2. Format each partition as FAT16 or FAT32. Do not use exFAT or NTFS.
  3. Copy your files to it. Files saved by ADOS keep their SAM type through their .info files; other files load as CODE.

8. Real-time clocks

When a clock is fitted, ADOS stamps every file you save with the date and time, on SAM and FAT drives alike. There is nothing to set up: the clock is found when ADOS starts, and the start-up screen shows which one it is and what it says the date and time are, for example AL Clock Present  Date: 20 Nov 2026 14:37:19.

ClockStart-up screen shows
Atom Lite clock (AL+)AL Clock Present
SAMBUS clockSAMBUS Clock Present
Dallas clockDALLAS Clock Present

If more than one clock is fitted, ADOS uses the first it finds, in the order of the table. On a SAM drive the date stamp is stored where MasterDOS keeps it, so MasterDOS shows the same date for the file. On a FAT drive it is the date the file was written, which a PC shows; the dates it was created and last opened are left empty. If the clock is not set, or gives a date that cannot be right, the start-up screen shows Not Set, SAM files are saved without a date and FAT files are dated 1 January 1980.

Appendix A. DOS hook codes

Machine code programs call ADOS through the ROM's DOS hook codes, as with SAMDOS: put the arguments in the main registers, then RST 8 followed by the hook code. Results come back in the alternate registers. Errors end in a BASIC error, unless DVAR 48 is set (Appendix B): then carry is set in F' and A' holds the error number. Hooks from 128 to 194 that ADOS does not list below do nothing. Hook 195 gives a long name for the next hook that reads a header (below). A code outside 128–195 gives Bad hook.

Long names. A header has room for a 14-character name. Hook 195 gives a longer one, up to 255 characters, with a drive, a path and a FAT long name allowed as in LOAD. The next hook that reads a header (129–132, 158, 165 or 166) uses it in place of the header's name, once. The arguments are those of hook 145: A = the page, DE = the address as if that page were in section C. With BASIC's paging, a name at 16384–32767 is page 0 at the address + &4000, one at 32768–49151 page 1 at the same address, and one at 49152–65535 page 2 at the address − &4000. Call 195 just before that hook: anything else that reads a name in between, or any BASIC error, cancels it. It also works through the direct entry.

BDOS hooks. Drive 1 is A:, drive 2 is the BDOS card in use (B: if there is none), and a letter such as "C" can be given instead. The sector hooks work on any SAM drive: a floppy, the current BDOS record, or a disk image. For 160 and 149 the address is read as BASIC’s memory is paged (16384–65535, pages 0–2). A track and sector that isn’t on the disk gives Disk error. Docs/Hooks.md lists the BDOS DVARs and the details.

158, 159 and 161 have the same numbers and arguments as in MasterDOS and BDOS. A stream reads one file a piece at a time, from any position, on any drive, including inside a disk image. Positions count data bytes only, so position 0 is the first byte of the data on every drive. Streams are read only. A stream hook with no file open gives File not open, except 194 (close).

Is ADOS loaded? Codes 192 and up are ADOS's own, and MasterDOS crashes on unknown codes above 174, so check first. DOSFLG (&5BC2) is 0 if no DOS is loaded. Otherwise read DVAR 7 through hook 139, which every DOS has (from BASIC, PEEK DVAR 7): ADOS holds version × 10 + 50 there, 62 for ADOS 1.2. To be certain it is ADOS and not another DOS using the same number, also check for the letters ADOS at offset &0212 of the DOS page, followed by the version (major, minor). Docs/Hooks.md has the code for both.

Direct entry (from 1.1). A program that has taken the machine over (ROM 0 paged out, the system variables reused, its own interrupts) can't use RST 8. Instead it pages the DOS page into section C and calls offset &0209 in it, with the hook code in the byte after the call: CALL &8209 / DB 161. The arguments and results are the hook's, in the main registers. An error comes back to the program with carry set and A = the error number. Hooks 132, 145, 158, 161, 192–194 and 195 can be called this way; for 161, C gives the page to read into. The paging and interrupt state are as they were. Interrupts stay on except while a piece of data is copied, so an IM2 handler kept in the page after the DOS page keeps running. Docs/Hooks.md has the details.

Seeking reads only the sector the new position is in. On FAT it follows the cluster chain without reading the data. A SAM file whose sectors are in one run (as SAVE makes them when there is room) goes straight to the right sector. Other SAM files are read through, because each sector holds the link to the next.

The ADOS source includes Docs/Hooks.md, with full details and a worked example.

The code that finds the drives is only needed at start-up, so it runs from a spare memory page and takes no room in the DOS page.

In the system page ADOS keeps a 32-byte routine at &4BA0, and points the ROM's RST8V vector (&5AEE) at it. ROM 3.0 refuses a LOAD or SAVE name over 14 characters with error 18, and its error handler calls RST8V first. For that error the routine passes the whole name to ADOS (hook 195), then lets the ROM carry on as if the name were 14 characters. Every other RST 8 goes straight through. ADOS puts the vector and routine back whenever the DOS is initialised (hook 135).

Appendix C. Planned features and known limits

Known limits in this version

  • FAT12 drives are shown at start-up but cannot be read. GPT partition tables are not supported.
  • Dates on FAT: DIR does not show dates, and RENAME gives a FAT file the time of the rename.
  • Single-drive copies: MasterDOS asks you to swap disks when copying from one floppy to another in the same drive. ADOS does not, so copy through a second drive or a disk image.
  • Inside a disk image, the DIR heading and PATH$ show only the path inside the image, not the FAT folder and image name.
  • New cards and drives are found only when ADOS starts.
  • Streams are read only, and don't notice a floppy being changed while a file is open (close the file, change the disk, and open it again).
  • Long listings: a long wildcard COPY or DIR stops at the ROM's Scroll? prompt when the screen fills, as in SAMDOS.
